DOKUMENTÁCIA PROJEKTU: IPC Komunikačný Systém
1. Text zadania
Cieľom projektu je navrhnúť a implementovať systém spolupracujúcich procesov v prostredí OS Linux, ktoré demonštrujú rôzne mechanizmy medziprocesovej komunikácie (IPC). Úlohou je vytvoriť "pipeline" spracovania dát, kde vstupom sú textové súbory a výstupom je jeden agregovaný súbor.
Systém pozostáva z reťazca procesov:
P1, P2: Čítajú slová zo vstupných súborov.
Pr: (Dodaná binárka) Spracováva vstupy a posiela ich ďalej.
T: Prenáša dáta z rúry do zdieľanej pamäte.
S: (Dodaná binárka) Spracováva dáta v zdieľanej pamäti.
D: Vyberá dáta zo zdieľanej pamäte a posiela ich cez TCP.
Serv1: (Dodaná binárka) TCP server/UDP klient, preposiela dáta.
Serv2: UDP server, zapisuje finálne dáta do súboru.
2. Dodefinovanie zadania – špecifikácia obmedzení
Realizácia sa riadi nasledujúcimi technickými obmedzeniami a špecifikáciami:
Obmedzená veľkosť prenosu: Všetky dátové buffre sú limitované konštantou MAX_BUFFER (152 bajtov).
Pevné identifikátory IPC: Zdieľaná pamäť a semafóry musia používať kľúče definované v common.h (1234, 5678, 1111, 2222), aby bola zaručená kompatibilita s dodanými binárnymi modulmi (proc_s).
Synchronizácia: Procesy P1 a P2 nesmú čítať dáta svojvoľne, ale musia byť riadené signálom SIGUSR1 (vyžaduje to modul Pr).
Sieťová komunikácia: Porty pre TCP a UDP komunikáciu nie sú pevne zakódované ("hardcoded"), ale odovzdávajú sa ako argumenty príkazového riadku pri spustení hlavného procesu.
Architektúra: Riešenie je navrhnuté ako jeden riadiaci proces (zadanie), ktorý spúšťa a spravuje všetky podprocesy.
3. Popis relevantných štruktúr a dátových typov
Pre zabezpečenie konzistencie naprieč celým projektom je použitý hlavičkový súbor common.h, ktorý definuje:
shared_data_t: Štruktúra pre prenos dát cez zdieľanú pamäť. Obsahuje jediné pole char text[MAX_BUFFER]. Tým je zabezpečené, že všetky procesy pristupujú k pamäti rovnako.
union semun: Nevyhnutná únia pre inicializáciu semafórov pomocou volania semctl (štandard System V IPC).
IPC Kľúče: SHM_KEY_1/2 a SEM_KEY_1/2 slúžia na jednoznačnú identifikáciu prostriedkov v systéme.
Názvy súborov: Konštanty FILE_P1, FILE_P2 a FILE_OUT definujú vstupné a výstupné cesty.
4. Analýza problematiky
Zadanie predstavuje klasický problém producent-konzument aplikovaný v sérii (reťazci). Hlavnou výzvou je rôznorodosť komunikačných kanálov.
Tok dát:
Súbor -> Rúra (Pipe) -> Zdieľaná pamäť (SHM) -> TCP Socket -> UDP Socket -> Súbor.
Analýza možností synchronizácie pri SHM:
Alternatíva A (Busy waiting): Proces by neustále kontroloval príznak v pamäti.
Mínus: Extrémne zaťaženie CPU.
Alternatíva B (Semafóry): Použitie System V semafórov pre blokovanie procesu, kým nie sú dáta pripravené.
Plus: Efektívne využitie CPU, proces spí, kým nie je na rade. Toto riešenie bolo zvolené.
Analýza spúšťania procesov:
Bolo nutné zvoliť hierarchiu procesov.
Riešenie: Jeden hlavný proces (zadanie.c) vytvorí všetky IPC zdroje a následne pomocou fork() a exec() spustí robotníkov. Toto zaručuje, že zdroje existujú skôr, než sa k nim procesy pokúsia pripojiť.
5. Popis navrhovaného riešenia
a. Návrh riešenia
Zvolil som kombináciu rúr (pipes) pre lokálnu komunikáciu rodič-dieťa (medzi P1/P2, Pr a T) a System V IPC (SHM + SEM) pre komunikáciu medzi nezávislými procesmi (T, S, D). Pre sieťovú časť sú použité štandardné BSD sockety. Dôvodom je robustnosť a fakt, že semafóry poskytujú atomické operácie potrebné pre bezpečnú synchronizáciu zápisu a čítania v zdieľanej pamäti.
b. Dátové štruktúry
Semafórové polia: Každá zdieľaná pamäť je chránená poľom dvoch semafórov:
Index 0: Indikuje "voľno pre zápis" (Write Mutex).
Index 1: Indikuje "dáta pripravené na čítanie" (Read Mutex).
Buffer: Všetky procesy používajú staticky alokované pole char buffer[MAX_BUFFER] pre manipuláciu s reťazcami pred ich odoslaním.
c. Spôsob synchronizácie
Synchronizácia je kľúčová, aby nedošlo k prepísaniu dát skôr, ako sú prečítané.
P1/P2: Synchronizácia pomocou signálu SIGUSR1. Proces spí (pause()) a zobudí sa až po prijatí signálu od procesu Pr.
T -> S -> D: Synchronizácia semafórmi.
Producent (napr. T): Čaká na semafor 0 (Wait for Write). Zapíše dáta. Zvýši semafor 1 (Signal Read).
Konzument (napr. S): Čaká na semafor 1 (Wait for Read). Prečíta dáta. Zvýši semafor 0 (Signal Write).
Inicializácia semafórov v zadanie.c je nastavená na {1, 0}, teda zápis je povolený, čítanie blokované.
d. Algoritmy
Algoritmus hlavného procesu (zadanie.c):
Vytvor IPC zdroje (SHM, SEM).
Inicializuj semafóry na hodnoty {1, 0}.
Vytvor rúry (pipes) pre P1/P2->Pr a Pr->T.
Postupne forkuj a spúšťaj procesy (execl). Dôležité je presmerovanie stdin/stdout pre procesy využívajúce rúry pomocou dup2.
Čakaj na ukončenie synov (wait).
Pri ukončení (aj cez Ctrl+C) uprac zdroje (shmctl, semctl s príznakom IPC_RMID).
Algoritmus Procesu T (Writer do SHM):
Pripoj sa k SHM1 a SEM1.
Čítaj stdin (presmerovaná rúra od Pr).
semop(WAIT, index 0) -> Zámok pre zápis.
strcpy dáta do SHM.
semop(SIGNAL, index 1) -> Odomkni pre čítanie.
Algoritmus Procesu D (Reader z SHM + TCP klient):
Pripoj sa k SHM2 a SEM2.
Vytvor TCP socket a pripoj sa k localhost:port1.
V cykle:
semop(WAIT, index 1) -> Čakaj na dáta.
Prečítaj dáta, pošli cez send().
semop(SIGNAL, index 0) -> Uvoľni miesto pre ďalší zápis.
Algoritmus Procesu Serv2 (UDP Server):
Vytvor UDP socket a binduj na port2.
V nekonečnej slučke rob recvfrom().
Prijaté dáta zapíš (append) do súboru serv2.txt.
6. Záver a zhodnotenie
Časová náročnosť:
Implementácia a ladenie trvalo približne 8 hodín. Najviac času zabralo správne nastavenie IPC kľúčov a pochopenie správania binárnych modulov (Pr, S), ktoré vyžadovali špecifické semafórové operácie.
Hodnotenie a obmedzenia:
Výsledný systém je funkčný a stabilný. Dáta prechádzajú celým reťazcom bez straty a v správnom poradí.
Obmedzením je použitie INADDR_ANY a localhost v kóde, čo znamená, že distribuovaná časť je simulovaná na jednom stroji. Pre skutočné sieťové nasadenie by bolo nutné parametrizovať aj IP adresy. Ďalším obmedzením je absencia sofistikovaného error-handlingu (napr. pri výpadku siete sa procesy ukončia).
Výsledok:
Výstupný súbor serv2.txt obsahuje korektne poskladané reťazce, napr. jeden-pr-s-d-serv1, čo potvrdzuje úspešnú synchronizáciu všetkých 7 procesov.

PRÍLOHY
8. Systémová príručka (Pre programátora)
Projekt je rozdelený do modulov, pričom common.h slúži ako spojovací prvok.
Modul common.h:
Definuje dátové štruktúry. Kľúčová je shared_data_t, ktorá zabezpečuje binárnu kompatibilitu pamäťového rozloženia medzi mojimi a dodanými procesmi.
Modul zadanie.c (Main):
Toto je "orchestrátor".
void cleanup(): Funkcia volaná pri ukončení (aj cez signál SIGINT). Zabezpečuje odstránenie IPC objektov zo systému, aby nedochádzalo k "memory leakom" v jadre OS.
main(): Zabezpečuje fork, dup2 (pre rúry) a exec. Logika vytvárania procesov je sekvenčná, s krátkymi sleep(1) pre stabilizáciu serverov pred spustením klientov.
Modul proc_p1.c / proc_p2.c:
Implementujú pasívne čítanie.
void my_handler(int): Obsluha signálu SIGUSR1. Nastavuje globálnu premennú volatile sig_atomic_t ready_to_send, čo je jediný bezpečný spôsob komunikácie so signálovým handlerom.
Modul proc_t.c:
Prekladá prúd dát (stream) na bloky zdieľanej pamäte.
Využíva sembuf štruktúry pre operácie -1 (wait) a +1 (signal).
Modul proc_serv2.c:
Jednoduchý UDP server.
Otvára súbor v móde "a" (append) pri každom prijatom pakete, čo je síce menej efektívne ako mať súbor otvorený stále, ale bezpečnejšie z hľadiska konzistencie dát pri páde.
9. Príručka používateľa
Účel programu:
Program slúži na demonštráciu toku dát cez rôzne typy IPC. Spracováva obsah súborov p1.txt a p2.txt a výsledok ukladá do serv2.txt.
Závislosti:
OS Linux/Unix.
GCC kompilátor.
Vstupné súbory p1.txt, p2.txt v rovnakom adresári.
Spustiteľné súbory proc_pr, proc_s, proc_serv1 (súčasť zadania).
Kompilácia:
Pre zostavenie všetkých modulov použite príkaz (ak je dostupný Makefile):
code
Bash
make
Alebo manuálne:
code
Bash
gcc zadanie.c -o zadanie
gcc proc_p1.c -o proc_p1
gcc proc_p2.c -o proc_p2
gcc proc_t.c -o proc_t
gcc proc_d.c -o proc_d
gcc proc_serv2.c -o proc_serv2
Spustenie:
Program vyžaduje dva parametre: TCP port a UDP port.
code
Bash
./zadanie <port_tcp> <port_udp>
Príklad:
code
Bash
./zadanie 8080 9090
Popis činnosti:
Po spustení program automaticky naštartuje všetky podprocesy. Na konzole uvidíte výpisy o štarte serverov a ukladaní dát. Program beží, kým nespracuje všetky vstupy, alebo kým nie je ukončený používateľom.
Ukončenie:
Stlačte Ctrl+C v termináli, kde beží zadanie. Program zachytí signál a korektne ukončí všetky podprocesy a vymaže zdieľanú pamäť.
Výstup:
Skontrolujte súbor serv2.txt. Mal by obsahovať spracované slová.
